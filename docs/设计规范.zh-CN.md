# EDK 设计规范（1.0.0）

## 当前定位

EDK 1.0.0 交付环境派生密钥的概念算法与参考实现，以及支撑研究的观测、仿真、SRAM 主机程序、数学论证和发行验证工具。它尚未完成真实环境与电子节点的长期工程验证。版本号标识这套软件，不代表硬件寿命或密码学安全强度已经得到验证。

## 设计目标

EDK（Environment-Derived Key，环境派生密钥）研究一种依赖维护的秘密生命周期：**现实物理环境参与秘密形成与恢复，主人持续维护环境时保持可恢复性，长期失养后则可能丢失与原始秘密有关的历史信息。**

维护可以包括稳定读取、修复轻微物理变化，以及在门限仍满足时更换损坏的电子节点。失养后，密文仍可完整存在，而重建原密钥所需的物理信息可能减少。

“信息性死亡”指在明确攻击者知识、能力、时间和资源后，原始秘密的实际恢复概率下降。它不表示密钥在数学上不存在，也不能由一次解码失败或热力学熵增加直接推出。攻击者已经复制的历史信息不会因原环境后来的变化而消失。

## 双源结构

设 `X0` 是登记时的环境状态，`Xt` 是当前观测，`M` 是公开的锚点 Manifest。`KV` 是独立生成的 256 bit 随机电子秘密，由六份 Shamir 份额以 3-of-6 门限保存。环境信息和电子秘密共同参与最终派生：

```text
现实物理锚点 -> 当前精确观测 -> 版本化环境编码 E --+
                                                 HKDF -> 12 位数字 PIN
六个易失节点 -> 至少三份兼容份额 -> KV ------------+
```

环境不能被公开的房间名称、地址或固定字符串代替；六个存储设备放在不同地点也不构成环境派生。电子节点提供第二秘密源及维护机制，环境源必须有独立的实际安全贡献。

当前参考算法可以写为：

```text
E   = exact_observation_bytes(M, Xt)
KV  = recover(compatible_shares)
PIN = derive_pin(E, KV; public_salt, device_id)
```

`E` 是经过严格校验的环境输入编码，还不是经证明的高熵提取结果。双源输入门控证明协议要求两个输入，并不自动证明其中一个泄露后，另一个还提供多少条件最小熵。12 位 PIN 的输出空间本身也限制了安全强度，最多约为 39.86 bit。

## 精确输入参考算法

`derive_observation_pin(manifest, session, shares, context)` 将版本化环境观测与现有 Shamir/HKDF 实现连接。公开上下文固定 Manifest、32 字节盐和设备标识；读取规则、锚点顺序及状态范围由登记 Manifest 确定。

所有锚点必须给出范围内的正常读数。模糊读数和不可读取状态会停止派生，当前算法不自动接受相近值。`concept-run` 使用内存中的合成观测和份额，检查二十种 3-of-6 组合、节点修复及异常输入拒绝，完成后输出检查结果而不输出 PIN。

范围内已经变化的环境值，或恰好达到门限的一组被篡改份额，仍可能产生不同 PIN。输入格式与一致性校验不等于真实性认证。

Manifest 的标识、规则文字、位置提示、状态数量和顺序都参与公开指纹。修改这些内容会改变参考输入，因此应保留登记版本。观察者代号、采样时间等研究元数据不参与密钥派生。

软件版本、输入 profile 与密码学协议版本分别管理：

| 对象 | 兼容性含义 |
|---|---|
| 软件包 `1.0.0` | 当前概念算法、API 与工具的版本 |
| 旧原始字节输入 profile | 保留原有有效输入的 PIN 测试向量 |
| Manifest 绑定的精确观测 profile | 使用版本化编码、公开 Manifest 指纹与固定宽度状态值 |
| `EDK-LAB/v0.1-alpha` KDF 域 | 继续保留的派生字节域，不随包版本改名 |
| JSON `/v1` 与 SRAM 记录版本 | 各自的数据格式与解析规则 |

旧字节 profile 与新的观测 profile 编码不同，对相同物理读数不承诺得到同一个 PIN。跨 profile 迁移必须明确选择，不能通过改包版本隐式替换。

## 环境观测与实验

公开 Anchor Manifest 为每个现实对象规定锚点标识、定位提示、读取规则和状态数量，不强制采用规则网格或每锚点 64 态。秘密物理状态、详细住址、敏感定位信息和访问凭证不属于公开 Manifest。

观测明确区分正常、模糊和不可读；实验分析分别记录读取时间、缺读、正常读数间差异、外部标注事件与相关变化。差异本身不能自动判断是误读还是环境真的改变，外部标注也不是历史信息消失的证明。

研究原始记录保存在受保护的本地位置，公开报告只导出聚合结果。原始历史记录一旦保留，就必须纳入可能存在副本的攻击模型，不能充当真实密钥生命周期的永久恢复通道。`StudyPolicy` 让研究者显式声明样本数、观察者数、时间跨度和读取质量阈值；达到这些阈值表示采样质量符合该研究协议，不表示环境熵已经验证。

早期 `40 个 Cell × 每个 64 态` 是旧测试 profile，240 bit 是编码空间的描述。实际不可预测性需要结合偏差、相关性、照片、近距离观察及其他背景知识评估。若找不到满足维护、读取与保密要求的物理状态，应记录否定结论。

有噪声恢复仍需研究成熟的 Secure Sketch/Fuzzy Extractor 构造、公开辅助数据泄露和误恢复行为。任意环境符号不天然构成 Reed–Solomon 合法码字，不能直接把 RS 解码等同于环境恢复。

## 六节点与易失性存储

六节点的预期角色如下，部署时要分别分析地点、供电和安全独立性：

| 节点 | 预期位置与维护关注点 |
|---|---|
| S1 | 随身携带，考虑遗失、被盗与供电维护 |
| S2 | 居所抽屉，周期补充能量 |
| S3 | 第二独立地点，避免与 S2、S5 同址形成门限 |
| S4 | 车辆内部，考虑高温、储能器件条件与盗窃 |
| S5 | 居所持续外部供电节点，仍有非零故障风险 |
| S6 | 办公室的独立第六份额，不复制其他节点的字节 |

当前硬件路径是 Linux／Raspberry Pi I²C 主机配合 MCP7940N 的 64 字节备用 SRAM。已实现寄存器读写、记录编码、提交前读回、配置校验、写入日志和只读检查；该路径无需额外 MCU 固件。

写入日志先持久化计划及每个槽位的写入意图，再执行设备操作。缺少成功回执的意图表示状态不确定，不自动重试。六个独立设备之间不具备分布式原子提交；CRC 用于发现偶然损坏，不是份额认证。

确认损坏且原份额已不可恢复的节点，可以在仍有三份健康份额时重建原坐标。丢失、被盗或可能复制的份额需要单独的泄露处置，简单重写原份额不能撤销旧副本。攻击者已经取得同代次门限份额时，仅刷新份额不能使其忘记原 `KV`。认证及协调刷新还需要独立设计，不能假设 64 字节足以同时容纳多代记录和事务元数据。

## 数学论证与信息性死亡指标

[形式规范与数学论证](FORMAL_SPEC.md) 讨论理想 Shamir 的恢复、修复和保密性，带假设的历史信息擦除模型，PIN 拒绝采样映射，以及 SRAM 提交和日志顺序不变量。通用论证与有限模型检查互相补充，物理前提则需要实验。

这些指标应分别记录：

1. 按既定流程完成正常恢复的概率。
2. 电子份额仍满足门限的概率。
3. 环境原始信息在指定模型下仍可恢复的概率。
4. 整体系统在指定模型下可恢复的概率。
5. 给定攻击者信息和验证渠道后的秘密猜测成功率。

仿真中的读取错误、物理状态擦除和真正历史信息损失是不同变量。独立失效、同址事件、车辆应力及维护周期的参数目前是合成假设。SRAM 掉电、常规读取不匹配和取证意义上的不可恢复也需要不同证据，不能用软件模型互相替代。

公开 PIN 哈希、密文认证标签或其他校验渠道可能提供离线猜测验证器。条件安全分析必须把这些渠道和已经取得的历史副本计入攻击者知识，而不能仅依赖目标硬件的在线尝试次数。

## 软件验证与后续证据

软件验证覆盖输入校验、旧派生向量、门限组合与修复、缺失或混代次拒绝、观测研究流程、合成生命周期、SRAM 中断、日志状态和发行包一致性。具体执行环境和结果以各次验证记录为准；测试配置不代替实际运行结果。

下一步围绕真实环境来源、鲁棒恢复、单节点电源、六节点故障、认证与刷新、数学审查和目标平台验收形成研究工作包。长期保持、历史信息衰变和实体读取风险需要持续测量。详见[路线图](ROADMAP.md)、[实验计划](EXPERIMENTS.md)、[硬件分析](SRAM_ENGINEERING.md)及[工程运行手册](ENGINEERING_RUNBOOK.zh-CN.md)。
